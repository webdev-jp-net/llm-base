# ドキュメントレビューユーティリティ

Codex CLIを使用してドキュメントをレビューし、結果を返す。

## 実行コマンド

リクエストは引数ではなく標準入力から渡す。レビュー対象にはバッククォートや `$()` が含まれるため、
シェルの二重引用符に埋め込むと外側のシェルが展開してしまう。

```bash
codex exec --full-auto --sandbox read-only --cd <project_directory> < <request_file>
```

## プロンプトのルール

**重要**: codexに渡すリクエストには、以下の指示を必ず含めること：

> 「確認や質問は不要です。具体的な指摘まで自主的に出力してください。」

## ワークフロー

### Step 1: レビュー対象の特定

以下の優先順位でレビュー対象を特定する：

1. `$ARGUMENTS`にファイルパスが指定されている場合 → そのファイルを対象にする
2. 呼び出し元のコンテキストにドキュメントパスや内容が含まれる場合 → それを対象にする
3. 上記いずれも該当しない場合（自然言語で対象未指定）→ **git差分を対象にする**

#### git差分を対象にする場合

```bash
git rev-parse --verify HEAD
```

- **コミットがある場合**: `git diff HEAD` で差分を取得する（未ステージとステージ済みの両方を含む）。空なら対象なしとして終了する
- **コミットが1つも無い場合**: `git status --short --untracked-files=all` が挙げた未追跡ファイルの内容を対象にする

取得した差分のうち、`.md` や `.txt` などドキュメントファイルの変更のみを対象とする。

### Step 2: リクエストをファイルに書く

Writeツールで `.claude/tmp/doc-review-request.md` に次の内容を書く。対象の中身もここに含める。

```markdown
以下の観点でドキュメントをレビューしてください。

【レビュー観点】

- 追記部分のみの詳細度が過剰に上がり、ドキュメント全体のバランスを崩していないか
- 順序性が必然でない場面で見出しにorderが混入していないか
- 解説意図のメタ補足（例：「項目定義（最小構成）」「バリデーション（最新）」）が入っていないか
- 改訂履歴を示唆する記述（例：「判定しない方針に変更したため削除」）が残っていないか
- テキスト校正エラー（例：英単語前後への不要な半角スペース混在）が残っていないか
- DRY原則に違反していないか
- YAGNI原則に違反していないか

対象: {$ARGUMENTS の内容、呼び出し元から渡された内容、または Step 1 で取得した差分}

確認や質問は不要です。具体的な指摘まで自主的に出力してください。
```

### Step 3: Codex CLIでレビュー実行

出力は全文をファイルへ保存する。`head` / `tail` で切ると読むべき指摘が消えたことに気づけない。

```bash
codex exec --full-auto --sandbox read-only --cd <project_directory> \
  < .claude/tmp/doc-review-request.md > .claude/tmp/doc-review-result.txt 2>&1
```

### Step 4: 結果を返す

Codexの出力を呼び出し元（ユーザーまたは他のスキル）に返す。
